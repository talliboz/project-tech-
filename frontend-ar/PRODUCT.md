# Product

## Register

product

## Users

Maintenance engineers, technicians, and dashboard operators using a prototype AR maintenance support system for public transport environments. They need to detect simulated infrastructure faults, understand severity quickly, and monitor synced reports from AR devices.

## Product Purpose

The frontend demonstrates a TRL 3 proof-of-concept for AR-assisted public transport fault detection. Success means the interface clearly shows simulated AR fault markers, severity counts, recent fault reports, and backend dashboard synchronisation without implying a production-ready system.

## Brand Personality

Calm, precise, operational. The interface should feel like a credible engineering tool, not a marketing site or a game.

## Anti-references

Avoid loud sci-fi dashboards, neon AR clichés, decorative glass panels, oversized hero sections, generic SaaS metric cards, and visual clutter that distracts from fault severity and system status.

## Design Principles

Prioritise scan speed over decoration.
Make severity visible without overwhelming the interface.
Use familiar dashboard patterns so the prototype feels credible.
Keep the AR scene subdued, with overlays acting as operational annotations.
Present the project as a working prototype, not a finished enterprise platform.

## Accessibility & Inclusion

Use readable contrast, visible focus states, semantic status text, and severity indicators that do not rely on colour alone.
